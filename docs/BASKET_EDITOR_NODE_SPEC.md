# 篮子编辑节点需求（Basket Editor Node — 待开发）

> 状态：**待开发**（需求定稿，未实现）
> 目标：让 LLM 的 tag 分析推荐能**安全地**落到篮子文件——先罗列修改项，用户批准后才执行。

## 1. 定位

- 新增一个 ComfyUI 节点：接收 **tag 分析/反推结果**，解析出「推荐新增 tag」，与现有篮子对比后**罗列修改清单**，用户批准后写入部署目录的篮子文件。
- **只作用于部署目录**：`H:\ComfyUI_Windows_portable\ComfyUI\custom_nodes\ComfyUI-bsawang\baskets\`。**不涉及开发项目仓库**（仓库副本需手动同步）。
- **半自动流程**：先罗列 → 用户批准 → 再执行。

## 2. 输入

| 输入 | 类型 | 说明 |
|---|---|---|
| `分析结果` | STRING | tag 匹配 / 反推分析输出（含「推荐新增 tag」的结构化文本或 JSON）|

## 3. 控件

| 控件 | 默认 | 说明 |
|---|---|---|
| 目标目录 | 部署目录 | 写入位置（固定部署目录；后续可考虑可配）|
| 应用模式 | 批准后应用 | 罗列清单后需用户确认才写入 |

## 4. 流程

```
1. 解析分析结果 → 提取「推荐新增」项（{篮子key: [选项]}）
2. 与现有篮子对比 → 生成修改清单
   - 新增哪些选项到哪个篮子
   - 已存在的选项 → 标「跳过」
3. 输出修改清单（STRING），等待用户批准
4. 批准后：校验 + 去重 + 原子写 → 写入部署目录篮子文件
5. 输出应用结果（成功 / 跳过 / 失败明细）
```

## 5. 安全设计

- **只追加选项**：不删改已有内容、不自动新建篮子（新建需手动）
- **去重**：已存在选项跳过，不重复添加
- **JSON 原子写**：临时文件 + rename，防止崩溃损坏篮子文件
- **非法输入**：非 JSON / 结构错误 → 明确报错，不写盘
- **授权把关**：不批准不写盘；批准后才执行

> 说明：本节点只操作**部署侧本地数据**（ComfyUI 内的篮子文件），无公开/远程边界，安全/NSFW 篮子同为本地数据，故**不做 NSFW 隔离**。

## 6. 权限说明

- **无 OS 权限瓶颈**：节点进程以用户身份运行，写部署目录（用户安装目录）权限足够
- **授权瓶颈**：由「批准后执行」机制把控——LLM 推荐不会未经确认直接落盘
